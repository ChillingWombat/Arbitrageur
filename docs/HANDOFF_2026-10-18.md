## 4. The recipes that work on this machine

`0xC0000409 STATUS_STACK_BUFFER_OVERRUN` and `rustc-LLVM ERROR: out of memory` are **not
code defects** — they are the commit limit. Proof: same commits green in the Linux
container; `cargo check` passes on the same Windows machine; the *identical* rustc command
extracted from the failing log exits 0 with `-C debuginfo=0` appended and OOMs without it.
Full evidence chain in `docs/DIAGNOSIS_2026-10-17.md` §8.9–§8.13.

**Build the desktop binary:**

```bash
CARGO_TARGET_DIR=target-win CARGO_PROFILE_DEV_DEBUG=0 cargo build -p arbitrageur-desktop -j 1
```

(~2m52s.) `-j 1` keeps the peak to one rustc; `debug=0` drops DWARF, the dominant
allocation. `injective-std` is pinned `debug = false` in the workspace profile for the same
reason (its generated DWARF is the single largest peak and has no debugging value).

**Clippy (exact CI command, scoped):**

```bash
CARGO_TARGET_DIR=target-win CARGO_PROFILE_DEV_DEBUG=0 cargo clippy -p arbitrageur-desktop --all-targets -j 1 -- -D warnings
```

clippy-driver is a compiler *plus* lint machinery and compiles dependencies too, so it
needs **more headroom than `cargo build`**: ~4 GB free crashed inside `injective-std`'s
metadata phase. Closing Chrome (64 processes, 11.6 GB of commit) restored ~8.4 GB and it
passed. If clippy OOMs, free memory before suspecting code.

**Smoke tests** (state + stronghold, ~4 min, dominated by the Argon2 rekey test):

```bash
CARGO_TARGET_DIR=target-win CARGO_PROFILE_DEV_DEBUG=0 cargo test -p arbitrageur-desktop --bin arbitrageur-desktop -j 1 -- stronghold::tests state::tests
```

The full desktop suite (~1013 s) has **not** been run on Windows — do it before trusting a
Windows-only regression fix.

Do **not** bother with: `RUST_MIN_STACK` (no effect on these failures), `-j 2/4` alone,
`CARGO_PROFILE_DEV_DEBUG=0` alone, or scripts that try to enable the page file — the
sandbox security policy blocks `-EncodedCommand` and `Start-Process powershell` outright.

## 5. The two real defects the Windows bring-up exposed

### 5.1 First-run abort on a clean machine (`44e5129`)

Symptom: launching the built desktop binary on a fresh Windows box panicked before
anything opened:

```
failed to open instance lock file: Os { code: 3, kind: NotFound }
```

Root cause: the single-instance lock (`fs2::try_lock_exclusive`) is taken **before**
`StateStore::open`, and only the store creates `~/.arbitrageur/`. Linux machines hid this
because the directory already existed from earlier runs — a classic "works on the dev box"
latent bug that only native testing on a clean profile surfaces.

Fix: `open_instance_lock()` in `main.rs` creates the parent directory first, then opens and
locks the file; `main()` matches `Acquired` / `Busy` (exit 1) / `Err` (panic with the path).
Two tests: creates a missing nested directory; refuses a second holder. Verified by
running the real binary from a clean `%USERPROFILE%` — it created
`.arbitrageur/{arbitrageur.lock,state.sqlite3,-shm,-wal}` and the engine logged normally.

### 5.2 `large_enum_variant` in `stronghold.rs` (`e1d0b18`)

Windows clippy (the CI lint flags `-D warnings`, scoped to the desktop crate — the scoping
matters, see below) flagged `Backend`: `Snapshot(Stronghold, PathBuf)` is 264 bytes
against the test-only `InMemory` variant's 32.

**Why nobody caught it — this one is still open:**

- CI *did* see this exact code, twice, and was green both times: runs `39043100037` @
  `92e3205` and `39045685268` @ `423d27a` both executed "Rust format and lint" (fmt plus
  the exact command `cargo clippy --workspace --all-targets --locked -- -D warnings`,
  clippy 1.96.0) against the pre-box enum — confirmed via
  `git show 423d27a:frontend/src-tauri/src/stronghold.rs`, which carries the identical
  `Snapshot(Stronghold, PathBuf)` / `#[cfg(test)] InMemory(…)` shape. The container run
  (§2) was green on the same shape (`InMemory` long predates `92e3205`; it arrived in
  `1c90ec2`).
- So "Linux clippy green, Windows clippy red, same code, same clippy version" is a **real,
  unroot-caused discrepancy** — not an artifact of CI never having seen the code. Ruled
  out so far: clippy version (1.96.0 both sides), the lint command, workspace membership,
  and platform-dependent layout anywhere in the size chain (the only `#[cfg]` field,
  `Frag::info`, is 16 B on both platforms).
- **Leading hypothesis (untested):** the Windows run was **scoped**
  (`cargo clippy -p arbitrageur-desktop --all-targets`) while CI and the container ran
  `--workspace` — feature unification differs between the two, and different features can
  change dependency type layouts. To settle it, run the *scoped* command in the Linux
  container (start Docker Desktop first — the user does this manually):

  ```bash
  docker run --rm -v "$(pwd)":/app -w /app arb-builder:1.96.0 \
    cargo clippy -p arbitrageur-desktop --all-targets -- -D warnings
  ```

  Red on Linux ⇒ the scope/feature unification, not the platform. Green ⇒ a genuine
  platform layout difference in the tauri/iota-stronghold type chain.

**Lesson that still stands:** when CI is unavailable, a local "green" is only as good as
the exact command and the exact tree it ran on. The container run here claimed green at a
mid-session checkout that was later labelled with the final hash; re-run lint **after**
the final commit is in place, on the tree you are about to push.

Fix: `Snapshot(Box<Stronghold>, PathBuf)` — the enum is uniform at 32 bytes, the stronghold
is opened once per app run so the allocation is irrelevant, and all three use sites
(construction, `Deref`, `save`) work through the `Box` unchanged.

## 6. Pitfalls encyclopedia (each of these cost real time)

- **`gh issue comment` mangles backticks** inside double quotes (bash command substitution
  runs them). Always pass the body with `gh issue comment -F file`. Also: a literal `|x|`
  inside a Markdown table cell breaks the table — rephrase.
- **9p/Docker bind mounts:** `node_modules/.bin/tsc` fails with `Exec format error` — call
  `node node_modules/typescript/bin/tsc` directly.
- **Stale `target/release` rmeta** makes rustc report `output file ... is not writeable`;
  `cargo clean --release` then rebuild.
- **`cargo test --bin` does not rebuild the binary** — you can silently test the old exe.
  Run `cargo build -p arbitrageur-desktop` first when validating runtime behaviour.
- **Background PowerShell tasks are reaped after ~2 minutes** in this environment; any
  long compile/test must go through the Bash tool's background mode.
- **Elevation is policy-blocked:** `-EncodedCommand` and `Start-Process powershell` are
  refused as LOLBin bypasses. Don't design workflows that need them.
- **Replaying rustc commands from logs:** `shlex` eats backslashes and backticks — escape
  with `cmd.replace("\\", "\\\\")` before splitting.
- **CI `timeout-minutes: 45` silently cancelled** the 46-minute desktop suite (looks like
  "cancelled", not "failed"); raised to 90 in `ci.yml`.
- **Argon2id in debug builds is ~29 s per snapshot operation.** The `stronghold` test
  module takes ~200–250 s; it is not hung (`docs/DIAGNOSIS_2026-10-17.md` §8.12).
- **Two container-build traps** (both fixed in-tree on 10-17, but you will feel them
  if you rebuild the image or bypass the fixes): `.cargo/config.toml` points
  `PKG_CONFIG_PATH` at `.sysroot/`, which holds newer `.pc` files but no
  `gobject-2.0.pc`/`glib-2.0.pc` (fails in `gdk-sys`); and `.sysroot` `.so` files on a
  Windows host are `IntxLNK` symlink placeholders, so `build.rs` now emits `-L`/rpath
  only when **every** `.so` starts with the ELF magic. Details: `DIAGNOSIS_2026-10-17.md` §1.
- **Docker Desktop is not running by default** and starting it needs the GUI (do not
  launch detached processes); the user starts it manually when container work is needed.
  The image is `arb-builder:1.96.0` with the repo bind-mounted at **`/app`**.
